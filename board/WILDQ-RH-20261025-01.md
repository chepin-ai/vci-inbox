## WQ-1 · 区间见证层 PASS 对外部数学界的信息增量恒等于零——它是不是纯粹的内部仪式？

**质疑**：「区间见证层 PASS、kernel 层未证、非 RH 证据」三件套中，第一项 PASS 的唯一对外可读内容是「T=100 有 29 个零点、T=1000 有 649 个零点被区间方法括住」（ZETA-INST-01 §1、LAB-CLOSE-EXT13 L31）。这个结论在任何公开库上**秒级可复现**：`mpmath.zetazero(649)` 一行调用即给出同等且更高精度的答案（ZETA-INST-01 §零共享代码自述生成器即调 mp.zetazero）。对外部数学界而言，该 PASS 不携带任何先前未知的数学事实。

- **后果推演**：若联邦任何对外件把「区间见证层 PASS」表述为成果而非内部管线演练记录，外部读者的第一反应是「这为什么值得登记」；更严重的是，PASS 的架构语言（层/链/证书/赎回）会把零信息增量包装成有信息增量的外观，构成叙事通胀。
- **检验方法**：请见证线回答一个二值问题——「删去整条 ζ 见证链，外部数学界的知识状态是否有任何改变？」若答案为否（本席预判为否），则一切对外表述必须降格为「内部流程演练」，且内部登记件中所有「链/层/PASS」字样旁应强制附「零外部信息增量」披露。
- 不确定标注：本席未审计 witness JSON 的逐字段内容，不排除其中有内部工程价值（如赎回记账法范本的流程验证），但**数学**信息增量为零的判定不依赖该审计。

## WQ-2 · T=1000 在 ζ 零点计算史上的真实位置：约 1925–1953 年水平

**质疑**：对照在案前沿与公开史料：Turing 1953 年在 Manchester Mark I 上已计算约 1104 个零点（高度 T≈1540），严格区间验证的外部纪录（Platt–Trudgian 2021 类工作，MONITOR-FRONTIER 未单独立条，本席按公开史料标注为**待复核**）在 3×10¹² 高度、万亿级零点量级。联邦见证高度「有限高度 T=100/1000 截断」**低于 Turing 1953 年的高度**，距外部严格验证前沿约 9–10 个数量级。R1–R9 簇（2/3 简单零点、83.69% 互异、8/9 简单或在临界线上）是渐近比例定理，与有限高度不同层——但即便同层比，T=1000 也不构成任何纪录、逼近任何纪录、或对任何纪录提供校验价值（外部纪录的下限早已覆盖 T=1000）。

- **后果推演**：「联邦见证的高度是否低到无足轻重」——答案是：就零点计算本身而言，是。它唯一可辩护的定位是「区间方法管线的最小可行演示」。若内部叙事默认该高度有任何数论分量，即是自我欺骗。
- **检验方法**：在 ledger 中为见证链高度登记一行「历史坐标钉」（Turing 1953: T≈1540；现代严格验证：T≥10¹²），强制一切后续引用携带该坐标；若任何件拒绝携带，即视为叙事通胀违规。
- 不确定标注：Platt–Trudgian 的具体高度数值本席未本轮一手核验，建议监视席补一条一次性登记钉死；Turing 1953 数字为公开史料通说。

## WQ-3 · ZetaAnchor.lean 是 20 行 Prop 定义——锚的价值被系统性高估

**质疑**：ZetaAnchor.lean 全文 40 行，实质内容三条 `def : Prop`，零证明、零实例（本席一手核读全文）。U17-KERNEL-PROBE-01 §5 确认其 kernel 可解析、公理白名单——但这只证明「这三行类型正确的文字被 Lean 读进去了」。任何熟悉 Lean 的读者 5 分钟可写出等价文件。**删除该文件，联邦见证链的对外可证断言集不变**（本来就是空集）。更尖锐：`zetaAnchorImpliesRHCriticalLine` 的**命名**声称 "ImpliesRH"，但其定义体（ZetaAnchor.lean L35–37）就是 RH 临界线半边的直接重述——它不蕴含任何东西，也没有任何蕴涵结构；命名自带一个未被任何定理兑现的蕴涵承诺，属命名级夸大，与联邦名值分离纪律的精神相悖。

- **后果推演**：锚被 ledger 记为「首次 Prop 式诚锚立案」「满足锚定纪律」（FSL L331），在治理面获得与其实质（纯陈述件）不相称的分量；U-17 族为其命名错位消耗了三批治理资源（见 WQ-5），投入产出比本身即是证据。
- **检验方法**：执行思想实验并请判定席书面回答——「若 ZetaAnchor.lean 今夜从仓中消失，哪一条对外断言、哪一项 kernel 检查、哪一份证书失效？」逐项列出；凡答案为「无」者，即该锚的当前价值为簿记价值，应在 formalization.yaml 的 main_results 中降格标注「陈述级锚，非结果」。
- 附注：本席不否认「诚锚」作为纪律装置的价值（防止把未证陈述伪装成定理）；质疑的是其价值被表述为见证链的承重构件。

## WQ-4 · 名值分离的裂缝：Lean 锚与 JSON 证书之间没有任何机器可检绑定

**质疑**：`zetaIsolationAnchor(T, w)` 的语义（ZetaAnchor.lean L25–26）只约束「零点尽在 w 中」；它不要求 w 的分量是零点、不要求 w ∈ [0,T]、n 与实际零点数无绑定。更关键的是：**证书的具体数值（649 个括号坐标、端点、宽度）从未进入 Lean 侧**——gap-registry 的 `proposition_ref` 只是一个锚名字符串（ZETA-INST-01 §GAP 登记）。也就是说，即使明天外部发现 zeta-iso-1000.witness.json 里某个括号坐标抄错了，Lean 侧没有任何机制会失败；「锚定」是字符串级引用，不是数据级焊接。与此同时，NS 侧 capAnchorP1 至少把证书参数（中心、半径）编码进了 Lean def（CapAnchor.lean L119–131）——ζ 侧连这一层都没有，两侧锚定强度不对称，登记口径却同格。

- **后果推演**：外部评审者追问「你的 kernel 工件与数值证书的逻辑关系是什么」时，诚实答案是「一个字符串引用」；任何「锚定」「焊接」措辞在此强度下均偏重。
- **检验方法**：要求见证线给出从 zeta-iso-1000.witness.json 到 `zetaIsolationAnchor 1000 (w := …)` 具体实例（649 个有理数坐标进 Lean）的机器可检映射方案，或书面确认「不做数据级焊接」并将一切「锚」字样降格为「引用」。

## WQ-5 · U-17 族闭合、U-04 销账：纯簿记层闭合，被登记为「完成度」进展

**质疑**：U-17 三错的实质（U17-ZETA-ANCHOR-REVISION-01 §一、§三）：formalization.yaml 两处命名空间拼写错误 + 一条 source 指针编号归属不符。修订内容 = 把 `NSGalerkin.` 改成 `ZetaAnchor.` 两处 + 改一个指针字段（FSL v52 L500「+19/-4」、v54 L517「+14/-1」）。**闭合前后，任何 kernel 可检断言集零变化**（探针前后 #print axioms 相同、Prop 定义未动一字）。U-04 销账（ADJUD-20261024-02 案B）的前置是「册仓登记 + 锚例 40-hex 升格」——同样是登记层动作。然而 ledger 将其记为「U-17 族闭合（提前 25 天）」（v54），「提前 25 天」的修辞把簿记速度包装成了数学/工程推进速度。

- **后果推演**：治理仪表盘的「U 族闭合数」虚增完成度叙事；外部若审视，会发现一个消耗三批治理资源的「族闭合」对应两处字符串勘误，反而暴露治理重心偏移。
- **检验方法**：在 ledger 为 U-17/U-04 补注「簿记层闭合，kernel 可检断言集变化 = ∅」；并建立分类纪律——登记层闭合与内容层闭合不得在同一「完成度」口径下计数。

## WQ-6 · 外部评审最可能的一击致命点：整条链的信任根基是未经核证的 Python 验证器

**质疑**：「区间见证层 PASS」的实际执行者是 ci/witness_zeta_verify.py 等 Python 脚本（生成器 mpmath 被 WS-37 律明示「无需正确性」，验证器用 mpmath.iv 初等函数 + 文献显式余项常数）。**验证器自身的实现正确性没有任何 kernel 级核证**——其可信度来自「≥20 pytest 全绿」（ZETA-INST-01 §精度预算），即测试抽样，非证明。Gabcke/Hiary 余项常数是否被正确转写进 Python、Brent 渐近级数的分支处理是否正确，全靠人审 Python 源码。换言之，整条「见证链」的信任链底端是「请相信我们的 Python 写得对」——这与它试图对标的 kernel 级信任（R1 的 Lean 工件、L1 的三重核验）不在同一信任等级，而纪律措辞三件套的对仗格式（「区间见证层 PASS、kernel 层未证、非 RH 证据」）在视觉上把两个不等级的信任并置了。

- **后果推演**：外部评审者只需问一句「验证器代码谁核证过」，全链的对外可核验叙事即坍塌为「自评」。
- **检验方法**：做一次盲测式演练——把仓内工件交给不了解本链的评审者，让其仅凭仓内材料回答「649 个零点的哪些位被谁、以什么信任等级保证」；若答案必须引用「审查 ci/*.py 源码」，则在案登记该信任等级为「代码审查级，非机器核证级」。

## WQ-7 · CERT-ψ-TRUNC 自述在其引用定理的适用范围之外——该证书的存在理由是什么？

**质疑**：ZETA-INST-01 §3 逐字披露：「本证书为 Dudek 定理适用范围（x>e⁶⁰）之外的点态管道演练，非定理实例」。x₀=10⁷+0.5，而 Dudek 形式要求 x>e⁶⁰≈1.1×10²⁶——**适用范围差了 19 个数量级**。即该证书在其自身援引的误差界定理根本不成立的区域运行，残差界 |残差|≤2x₀log²x₀/T₀ 在该点没有任何定理背书。文件对此诚实披露（值得肯定），但随之的问题是：一个自认「非定理实例」的证书，其 PASS 的数学内容是什么？答案只能是「管道演练」——那么它进入 gap-registry 作为「赎回记账法首个范本实例」三证书之一（ZETA-INST-01 §实例三证书），范本的首个实例即包含一个定理外演练件，范本的示范价值被其自身削弱。

- **后果推演**：外部若抽查三证书，最容易被抓的就是这一件；「非定理实例」披露防止了夸大指控，但防止不了「那你们证了什么」的追问。
- **检验方法**：登记 ψ-TRUNC 的证书性质为「管道演练件，零定理内容」，并从任何「证书计数」中剔除或单列；若未来要做定理实例，x₀ 须 ≥e⁶⁰，预算重估另案。

## WQ-8 · iso1000 完备性从 BLOCKED(B1) 到 PASS 的翻转：verdict 对实现路线敏感，稳定性无保障

**质疑**：KI-EXT11-1.md L16 在案：「iso100 完备性层降格『数值演示级』；iso1000 完备性维持 BLOCKED(B1) time-box 诚实登记」。此后 LAB-CLOSE-EXT13 L31 登记 iso1000 完备性 PASS，翻转依据是方法换代（旧盒包络路线退役、结点紧区间 L 折线直证路线启用，EXT16-SUP-01 L10/L42–44）。同一数学命题、同一高度，verdict 随实现路线在 BLOCKED 与 PASS 之间摆动——这说明「PASS」记录的是**当前实现的健康度**，不是命题的认证状态。若下一代实现更替再次引入缺陷（EXT16-SUP-01 自己就修正了宽度预算双计这一「T=1000 处为主导项」的公式错误，FSL L352），PASS 是否回退？回退规程在案吗？

- **后果推演**：「区间见证层 PASS」作为状态钉被跨批引用（MONITOR-FRONTIER §〇、§六），但其隐含前提是「当前实现未再发现缺陷」；该前提无失效触发器、无复跑日程。
- **检验方法**：为 iso1000 verdict 登记「路线依赖披露 + verdict 回退触发器清单」（发现公式修正级缺陷即自动回退待审）；补 iso100 完备性从「数值演示级」至今的当前状态钉（本席未在本批材料中见到其升回记录，**如实标注不确定**）。

## WQ-9 · 单 kernel 通道：对照联邦自己在案的前沿登记，探针信任规格已落后

**质疑**：MONITOR-FRONTIER-20261025-01 §六第 1/7 条自己在案建议：kernel 层工件「应默认」Lean kernel + 独立 nanoda 重放 + comparator 对拍三件套，且 L7 登记了 2026 年 Lean 内核嵌套归纳缺陷事件作为单 kernel 信任不足的依据。而 U17-KERNEL-PROBE-01 对四锚的复验**只有 Lean kernel 单通道**（§3 探针输出、§4 重编译均 lean 本体），无 nanoda/lean4checker/Tenet 类任何第二通道重放。联邦监测席已把双 kernel 登记为「2026 年 AI 数学主张的标准信任层」，联邦自身工件尚未达标——**自己登记的标准自己不满足**。

- **后果推演**：外部若以联邦自己登记的 L7/§六标准回检联邦工件，结论是「未达其自认的行业标准」；这是最易被引用的自相矛盾点。
- **检验方法**：对 ZetaAnchor/CapAnchor 补一次 nanoda 或 lean4checker 重放并落板；若因工件仅为 Prop 定义而判定「不值得」，则同时坐实 WQ-3（锚价值被高估）。
- 缓解注：锚件无证明、无 sorry，单 kernel 风险敞口确实小于定理件；但「规格落差登记缺席」本身仍是治理缺口。

## WQ-10 · G3′ 缺席探针是对外部依赖漂移脆弱的时间快照，无失效管理

**质疑**：G3′ 探针（ZETA-INST-01 §GAP 登记）以「`#check @HardyZFunction` 等 unknown identifier ⟹ 缺席 TRUE」判定 mathlib 缺口域，fail-closed 设计依赖对照组。但 mathlib 是高活跃上游（B1-INFRA-20261025-01 §3.2：master 超前联邦钉 283 提交，Loeffler–Stoll 的 ζ/L-函数线 L5 活跃且已刊）。一旦 mathlib 引入 Hardy Z 或区间层 ζ 设施，G3′ 判定自动失效，而 gap-registry 的 gap_pred 字段不会自动更新——**gap 记录将静默陈旧**。联邦钉死 mathlib v4.35.0 反而遮蔽了这一点：钉内缺席为真，但「缺席」作为对外陈述时若不携带版本与日期钉，即是从快照到全称的非法滑移。

- **后果推演**：若外部引联邦 gap-registry 说「mathlib 无 X」，而彼时 mathlib 已有 X，联邦登记件将成为错误信息源。
- **检验方法**：为 G3′ 类探针登记失效触发器（mathlib 钉前移即复跑）与每条缺席判定的「版本+日期」强制字段；本批 B1 已建议 cache 归档，可同窗办。
