## 一、R2B-03 · push 真值双通道规程（入册成文）

### 1.1 背景与缺口

FINDING-20261024-02 后入册规程「push 后必 ls-remote 验证真值，禁信管道 RC」（FSL v50 补登）方向正确，但 ls-remote 网络路径单一走 ghfast.top 镜像代理（`origin = https://ghfast.top/https://github.com/chepin-ai/vci-inbox.git`）。WQ-8 质疑成立在案（ADJUD §六 Q3-WQ-8「成立」）：**信任从本地管道转移至单一第三方代理**，代理被污染/劫持/中间人时可伪造远端 ref——push 实际失败而验证「通过」，或谎报失败诱发重复推送；代理链不稳定在案（v49 补登 ghfast 降速改 gh-proxy 竞速）。本规程将单锚升级为双通道对拍。

### 1.2 规程正文

**触发时机**：每次 `git push` 完成后、任何「已上链」记账之前，必执行双通道对拍。亦适用于一切引用远端真值的判定场合（merge 前实 fetch 复算、销记核验等）。

**通道①（代理道）**：`git ls-remote origin refs/heads/main` —— 经 ghfast.top 代理。
**通道②（直答道）**：api.github.com 直连 REST `GET /repos/chepin-ai/vci-inbox/git/refs/heads/main`，取 `.object.sha`。

**判定**：两通道返回 sha **逐字一致且等于本地刚推送的 HEAD sha** → 记 **VERIFIED**，方可记账「上链」。任一不一致 → 进入 §1.4 分歧处置，**不得记账**。

**凭证纪律**：通道② 凭证以名值引用 `gh_pat`（`/mnt/agents/.pivot-sec/gh_pat`），命令内以 `$(cat …)` 展开，**凭证值绝不落任何文本**；sha 为公开信息，可落账。

### 1.3 执行模板命令块

```bash
# === R2B-03 双通道对拍模板（push 后执行；repo root 内）===
LOCAL_SHA=$(git rev-parse HEAD)

# 通道①：ls-remote（ghfast.top 代理）
CH1=$(git ls-remote origin refs/heads/main | awk '{print $1}')

# 通道②：api.github.com 直连 REST（凭证名值引用 gh_pat，值不落文本）
CH2=$(curl -s -H "Authorization: Bearer $(cat /mnt/agents/.pivot-sec/gh_pat)" \
  https://api.github.com/repos/chepin-ai/vci-inbox/git/refs/heads/main \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['object']['sha'])")

# 判定
echo "LOCAL=$LOCAL_SHA"; echo "CH1(proxy)=$CH1"; echo "CH2(api)=$CH2"
if [ "$CH1" = "$CH2" ] && [ "$CH2" = "$LOCAL_SHA" ]; then
  echo "VERIFIED: 双通道一致且等于本地 HEAD —— 可记账上链"
else
  echo "DIVERGED: 进入分歧处置流程（规程 §1.4），禁止记账"
fi

# 可选深化（分歧或抽检时）：compare 确认本地 HEAD 是否在远端链上
# curl -s -H "Authorization: Bearer $(cat /mnt/agents/.pivot-sec/gh_pat)" \
#   "https://api.github.com/repos/chepin-ai/vci-inbox/compare/${LOCAL_SHA}...${CH2}" \
#   | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['status'], d['ahead_by'], d['behind_by'])"
```

### 1.4 分歧处置流程

**以 api.github.com 为最终真值的理由**（四条，按权重序）：
1. **TLS 终结点**：直答道 TLS 终结于 github.com 官方证书；代理道 TLS 终结于 ghfast.top，代理在密码学意义上即可读改写响应体——伪造 ref 对代理是零成本，对直答道须攻破 GitHub 本体或其 PKI。
2. **结构化响应**：REST 响应携带 `node_id`/`object.url` 等交叉字段，且通道经凭证认证，整体伪造成本远高于单行 ls-remote 文本。
3. **无前科 vs 有前科**：api.github.com 直连可用已实证（B1 §三、本规程首案）；ghfast.top 降速/切换前科在案（v49 补登），其信任属性、运营方、TLS 钉可行性无资料（WQ-8 不确定处登记）。
4. **无镜像延迟层**：REST 读 GitHub 本体数据库，不经镜像同步管道，无代理缓存/滞后层。

**分支处置**：

| 情形 | 判定 | 动作 |
|---|---|---|
| CH1 == CH2 == LOCAL | VERIFIED | 记账「上链」，落双 sha |
| CH2(api) == LOCAL ≠ CH1（代理落后/回旧值） | 以 api 为真值 → **VERIFIED（api）** | 间隔 ≥60s 复测 CH1 一次；仍落后则登记「代理滞后事件」入 FSL，本批可用，连续 2 批滞后则启动代理污染应对（下） |
| CH1 ≠ CH2 且 CH2 ≠ LOCAL（或 CH1 报成功而 api 无此 sha） | **以 api.github.com 为最终真值：push 未生效** | 冻结一切「已上链」记账；启动**代理污染应对**：① 代理标记失信，切换 push/ls-remote 远端至 github.com 直连（网络可行时）或备用代理；② fresh clone 异源核验远端链完整性（与 R2B-01 同次操作）；③ 通报判定席与 B1，事件入 FINDING 序列；④ 该代理须连续 3 批双通道一致方恢复信任 |
| 双通道皆不可达 | 真值未知 | 记账**挂起**；严禁退回「信管道 RC」（FINDING-20261024-02 教训）；待任一通道恢复后补拍 |

### 1.5 规程首案（2026-10-25 实测，本批）

| 项 | 值 |
|---|---|
| 本地 HEAD | `72c10cdc00f753bec52b819b61b3c9fa58cbebe8`（merge commit，FSL v58 批十五收口链顶） |
| 通道① ls-remote（ghfast.top） | `ab1b9f269c3f85f827fb293177a935092c1f758f` |
| 通道② api.github.com REST `.object.sha` | `ab1b9f269c3f85f827fb293177a935092c1f758f` |
| 对拍判定 | **双通道逐字一致 → VERIFIED**：远端 `refs/heads/main` 真值 = `ab1b9f26…` |
| 深化核验（compare API） | `72c10cdc0...ab1b9f26` → status=ahead / ahead_by=3 / behind_by=0：**本地 HEAD 完整在远端链上**，远端另有 3 提交（非本席推送；本席零 git 操作权限，未执行 push/fetch） |

首案结论：双通道规程可执行、增量成本为每批一次 API 调用（秒级），通道② 路径与凭证引用方式实测有效。
