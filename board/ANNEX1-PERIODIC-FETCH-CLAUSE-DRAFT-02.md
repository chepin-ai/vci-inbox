## 款四 · 周期同步（盲区封顶）款（v1.1 全稿）

### 款 4.1 条文

> **款四（周期同步，事件驱动形态）。** 本地克隆对 `origin/main` 之同步，除附则一款一之合并锚点外，增列**事件挂接同步**：下列任一事件唤醒点发生时，执行体须在事件处理前置位执行一次 `git fetch`（只读，不 merge 不 push）：
> (i) inbox-poller 被 KICK.md push 事件唤醒时；(ii) 批首开局与批收口仪式进场时；(iii) 监视席到场执行续扫时（其既有 fetch 即计）；(iv) 任何本地 git 写操作（merge/push/commit 类）执行前。
> 同一批内相邻事件点之 fetch 合并去抖（距上次 fetch 不足一拍间隔阈值者不重复执行，沿 M9 判式之阈值名引用）。**【R-A 增句】去抖不适用于款一之合并前 fetch——该款为合并锚点强制义务，不因去抖豁免。**
> **目标态**：本地真值盲区（＝距最近同步锚点时长，附则一款二定义）稳态封顶 **≤30min**（案 B R2 裁决登记参数）；本款不设任何 cron/schedule/定时轮询载体——节律由事件密度涌现，封顶目标为验收判据而非时钟实现。

### 款 4.2 执行细则

1. **fetch 通道与红区豁免**：本款之 fetch 一律走 ls-remote/fetch 代理通道（git 协议层，非 api.github.com 计费业务端点）——限窗令红区（rc=43）**照行不误**，代理通道不占业务限额、无需豁免清单项；业务端点零调用（M11 全程先例在案）。若代理通道自身不可达，该事件点 fetch 记「未执行（通道不可达）」入 E-1 表注记栏，不重试轰炸、不转业务端点硬闯。
2. **节律实现**：(i) 之挂接由 B1 于 inbox-poller 事件处理入口前置 fetch 调用（437 行全文核在案之现状：poller.py 无仓同步逻辑——本款即其最小增补面）。**【R-B 增句】授权边界明示：该改动仅限事件处理入口前置一次只读 fetch 调用；禁引入 schedule/定时器/重试循环/业务 api 端点调用；改动 diff 随实施要点落板并作为生效要件②之附件。** (ii)(iii)(iv) 为既有仪式/行为之前置一步，零新进程、零守护体。全部挂接点清单由 orchestrator 实施要点逐点核实落板后方得生效（生效要件②）。
3. **与附则一既有三款之衔接**：款一（合并锚点三值登记）不变，事件挂接 fetch 不产生登记义务、仅更新远端跟踪引用；款二（同步锚点与「距最近锚点时长」随载义务）之锚点定义**扩及**本款事件挂接 fetch——任何成功 fetch 即重置盲区起点（fetch 后本地 remote-tracking 已见远端 tip，引用本地 remote-tracking 作判据之有效窗自该 fetch 起算；本地 HEAD 仍仅以合并锚点为准，两层名值分列）；款三（E-1 表两栏常驻）增列第三栏「事件点 fetch 记录（次数/成功/未执行原因）」。
4. **盲区实测与上报**：监视席每批续扫以 reflog/时刻序列复算当批盲区分布（最大值/稳态值），入 E-1 表随载；稳态 >30min 或单点 >2h 量级（M9 判式）即登记异常行呈判定席。
5. **失败处置**：事件点 fetch 失败（非「未执行」）为**新增异常类**——锯齿定谳之反证哨兵（案 B R2 裁决附则一款三）自此含「fetch 尝试失败」实例子类，单次即登记呈裁，不累计阈值。

### 款 4.3 与 W30 令之相容性论证（事件驱动表述）

1. **禁令文本**：W30 令＝「事件驱动触发，禁止定时轮询」（CACHE-RELAY-KEEP-01 L12）；其适用先例（ADJUD-20261023-01 a-3）明示：会话端禁新定时型载体，义务以事件驱动形态存在即合规，「不得设立任何 cron/schedule/定时轮询载体」。
2. **本款形态核对**：本款不设立任何时钟驱动载体——无 cron、无 schedule、无定时器进程、无工作流 schedule 触发器；全部同步动作挂接于**既有事件源**（push 事件、批仪式、席位到场、写操作前置），事件不到则 fetch 不发——与 B7+B8「每批续扫合并复查项」之 W30 合规先例同构（批触发覆盖等价于日查之判例在案）。
3. **「≤30min」之定性**：系**目标态/验收判据**（实测盲区分布之验收线），非实现机制——机制层无任何「每 30 分钟」之时钟语义；若联邦事件密度不足以使实测盲区稳态 ≤30min，本款不自动升级为定时载体，而由监视席实测呈判定席：届时处置选项为 (i) 申请 W30 例外裁定（明文、限域、限载体），或 (ii) 评估平台侧/非会话端载体（涉平台能力处沿 E3 轨），或 (iii) 修订封顶参数——三者皆须复裁，执行线不得自行设立 schedule。
4. **结论**：本款与 W30 令相容；相容性之存续条件＝「零定时载体」与「封顶仅作验收判据」两条，任一撤除则本论证失效、须复裁。
