## 条款一 · 墓碑映射机制（WQ2-4 焦点裁 (a) 之落实）

**1.1 墓碑记录定义。** 每一拍（`weave/pulse/YYYYMMDD-HHMMSS.json`）被滚动删除或出清删除时，必须生成一条墓碑记录，字段如下（C-6 落实：六字段）：

| 字段 | 语义 | 备注 |
|---|---|---|
| `beat` | 拍名（文件名逐字） | 主键 |
| `sha256` | 删除前工作树文件内容 SHA-256 | 纯内容哈希（无 git 头） |
| `git_blob` | 删除时 HEAD 侧 git blob 对象名 | C-6 增列；git blob 名 = "blob <len>\0" 头＋内容之 SHA-1，与 `sha256` 字段**名值分列**，禁止混用 |
| `deleted_at` | 删除执行时刻（UTC(Z)，ISO8601） | 单时钟域 |
| `deletion_basis` | 删除依据条款 | 取值限：本条款草案经裁定后的条款号（裁定后回填，前向自指已登记）／存量出清专案号／判定席专案裁决号 |
| `mapping` | 映射去向 | 二选一或并置：(i) aggregate 摘要文件路径+该拍在摘要内的偏移键；(ii) ledger 行行号（append-only 台账） |
| `batch_id` | 所属删除批次号 | 与条款三 §3.4 批次 manifest 同名 |

**1.2 墓碑载体。** 墓碑集合落 `weave/pulse-archive-index/<周期>.json`（周期按 ISO 周或批号，由 B1 定并登记），该目录及其文件 **append-only、不参与滚动窗、不参与出清**；对墓碑文件自身的任何修改/删除即触发红线①（沿 R2 案四红线体例，ADJUD-R2-20261025-01）。

**1.3 顺序闸（先碑后删）。** 墓碑写入并提交**先于**对应拍的物理删除执行；删除批次 commit 必须含有或前置于墓碑 commit——「删除前 manifest 先入链并经 R2B-03 双通道 VERIFIED」为硬顺序（WQ2-4 裁决补此闸之缺口原文）。

**1.4 墓碑可解析性。** 任一在案文书（board/、FSL、裁决书）引用的拍名，在删除后须可经墓碑一步解析到 `mapping` 去向；映射去向对象（aggregate 摘要/ledger 行）自身灭失而墓碑仍指向之情形，登记为「**空碑事件**」，按条款四 §4.2 处置。

**验收判据：**
- A1：随机抽 ≥10 个已删拍名，`grep` 墓碑目录命中且六字段齐备；**对拍算法钉（C-6 落实）**：取墓碑拍名之历史 blob（`git cat-file`）重算内容 SHA-256，与 `sha256` 字段一致率 100%，且 `git_blob` 字段与历史树逐名相符；**抽样钉（C-1 落实）**：抽样由非执行席执行，或以可复现规程（等距抽样＋起点公布）留痕；
- A2：对任一在案拍名引用（活引用台账任取一条）执行「拍名→墓碑→mapping→内容」全链走查，链通；
- A3：构造性反测——删除批次中人为剔除一拍的墓碑，CI 机检（条款三 §3.4）必须在推送前拦截；
- A4：墓碑目录 `git log --diff-filter=D` 命中恒为空（append-only 机检）。

## 条款二 · 引用豁免清单机制（WQ2-4 焦点裁 (b) 之落实）

**2.1 豁免册定义。** 凡被 board/ 在案文书（含 FSL、裁决书、监视件、野问件、发现件）按文件名引用的 pulse 拍，一律登记入**引用豁免册**（载体：`weave/pulse-archive-index/citation-exemptions.json`，append-only 语义同 §1.2）；在册拍**不被滚动删除、不被出清删除**。**引用域明示（C-9 落实）**：引用域初期限 board/；specs/、governance/、receipts/ 等他处引用之入册评估列首批滚动后复核项（或登记限域理由）。

**2.2 登记规程（入册）。**
- (i) 初始建册：全仓 `grep -oE '[0-9]{8}-[0-9]{6}' board/`（C-8 落实：通用拍名形，无年度硬编码，跨年不漏检）建**活引用台账**（W2-P0-07 已裁动作，本草案直接征用），逐条标注引用件、用途、引用时刻；去重后拍名全集一次性入册。已知下限（WQ2-4 实测）：≥7 个拍名、散布 14 件，含 `20261022-173652/174209`、`20261024-214153/223603`、`20261025-052609/090639/093845`——初始册不得少于该集合；通用形命中之非拍名字符串（如纯数字串）逐条人工核语境剔伪；
- (ii) 增量登记：每批收口时重跑同一 grep（同 (i) 通用形），新命中拍名当批入册（脚本化，一行成本）；
- (iii) 任何席位发现新引用可即时申报入册，orchestrator 一批内核账。

**2.3 除名规程（出册，从严）。** 除名仅在三条件**同时**成立时准许：(a) 引用件自身经判定席裁决失效或明文放弃该证据钉；(b) 该拍已按条款一完成墓碑+永久归档（mapping 去向为 portal 外持久位或等效锚）；(c) 除名动议在 board 落一行宣告并静置一批无异议。除名记录（拍名/依据/时刻/动议人席别）append-only 留痕于豁免册尾部。

**2.4 豁免与滚动的优先级。** 滚动删除候选集生成后，必须与豁免册求差集方可执行；豁免册查询失败（文件缺席/解析错）一律按「全集豁免」fail-closed 处理，**禁止**在豁免册不可读时执行任何删除。

**验收判据：**
- B1：初始册与活引用台账 grep 全集逐名相等（机检 diff 为空）；
- B2：构造性反测——将一在册拍放入删除候选 manifest，CI 必须在推送前拦截；
- B3：豁免册临时改名模拟不可读，删除流程必须 abort 且零文件被删；
- B4：除名走查——任取一除名记录，三条件证据（裁决号/墓碑行/宣告行）齐备。

## 条款三 · 与 N=168 窗的接口语义（WQ2-5 裁决落实）

**3.1 窗语义取严。** N=168 为**计数**窗；拍频实测非恒定（双倍长间隔 23.9–24.3min 与 2.3min 补偿拍在案，MONITOR-SWEEP-20261026-02 §四），168 拍对应物理窗 5.6–14 天不等。故滚出条件为**两条件取严**：拍须同时满足 (i) 不在名序最新 168 拍之内，且 (ii) 留存时长 ≥7×24h（按拍名时间戳解析，单时钟域 UTC(Z)）；拍停摆（批十八第三故障模 ≥63min 静默前科，FSL v61）时计数窗定格而时间下限仍独立生效——「滚动窗」语义在故障模下不退化为无限留存、也不退化为提前删除。

**3.2 滚动边界定义（C-4 落实，起向消歧）。** 边界 = `git ls-files weave/pulse | sort` 名序中**自末尾倒数第 169 拍**；删除候选集 = 该边界向名序首部方向之全部满足 §3.1 双条件之拍（即：不在名序最新 168 拍之内 ∧ 留存 ≥7×24h）。**枚举真值源唯一 = `git ls-files`**；禁用 readdir 系枚举（ls/find/glob/`rm -rf`）——A2 实验 D 实证 rm -rf 不可触截断线后件，readdir 枚举将静默遗漏恰好不可见者（WQ2-5 (3)）；A3 定谳后该禁令加强：readdir 结果系缓存调制振荡列举（可见域 3999–4438 分钟级振荡），任何基于 readdir 的删除集在原理上不可复现。

**3.3 删除动作形态（C-5 落实，张力消歧）。** 逐拍按名 `git rm -- <拍名>`（或等效按名 unlink+git rm），禁止目录级通配删除；删除前对该拍执行 sha256 实测并写入墓碑（条款一）——**实测失败先按条款五 §5.2(ii) 三次复核闸（间隔 ≥5min、全部失败方成立）处置，暂态失败只登记观望态重试；复核后仍不一致或与 HEAD blob 对拍不符者，整批 abort（§3.4(iii)），不做批内单拍跳过**，并登记异常。

**3.4 批量删除的墓碑生成原子性。** 一个删除批次 = {墓碑写入、候选集 manifest、物理删除、push} 四元组，原子性判据：
- (i) **manifest 机检**：批次随附 CI 可机检 manifest，断言「删除集 == 名序最旧 k 件 ∩ 非豁免册 ∩ 满足双条件」三断言全真；
- (ii) **先碑后删**：墓碑 commit 在删除 commit 之前或同 commit 内（§1.3）；
- (iii) **推送前双通道 VERIFIED**：manifest+墓碑+删除集推送前经 R2B-03 双通道核验；任一断言失败或核验未过，整批 abort——**不允许部分生效**（已删未推者以 `git checkout -f HEAD -- weave/pulse` 复原并登记）；
- (iv) **豁免收窄**：append-only 豁免（J-ADJ3 案二原文）范围收窄成文为「CI 机检 manifest 完全吻合之名序最旧 k 件」，任何偏离即撤豁免并按红线①处置（WQ2-5 裁决原文）。

**3.5 存量出清分案。** 生效日须将存量（在案数：tracked 4431–4437，WQ2-4/A3 各时点实测）降至 <4000 的**一次性出清**与例行滚动**分案执行、分案核验，禁止合笔**（WQ2-5 裁决原文）；出清批次独立编 `batch_id`、独立 manifest、独立墓碑周期文件，删除依据条款字段填出清专案号。

**验收判据：**
- C1：对删除脚本做静态检查——枚举调用点唯一为 `git ls-files`，全文无 readdir 系枚举与 `rm -rf`/通配删除；
- C2：构造性反测三连——(a) manifest 多列一拍→CI 拦截；(b) 墓碑缺失一拍→CI 拦截；(c) 双通道核验强制失败→整批 abort 且工作树复原 D=0；
- C3：拍频抖动仿真（注入 2.3min 紧补拍与 24min 长间隔序列）下，双条件取严之删除边界与人工名序推演逐拍相等；
- C4：存量出清与首笔例行滚动的 batch_id、manifest、墓碑周期文件三者分离，无合笔痕迹；
- C5（C-11 落实，新增）：**推送后远端 tree 对拍**——`git ls-tree -r origin/main -- weave/pulse` 与本地删除后状态对拍零残差（沿三联对拍体例），结果入当批登记（条款七 §7.1 第四行）。

## 条款四 · 失效与回滚条款（v1 不动段——复核件过堂三性俱良，无必修项）

**4.1 条款失效条件（本草案所设机制自身之失效）。** 下列任一即触发墓碑机制**停用评审**（非自动废止，须判定席复裁）：(a) REDUCE 本身被复裁撤销；(b) pulse 目录改型（分片储备案①启用，J-ADJ3 案二）使滚动窗机制消灭；(c) 墓碑载体迁移（载体换代须新旧并账双写 ≥2 批方可切换）。

**4.2 运行期失效态与处置。**
- **空碑事件**（§1.4）：映射去向灭失——登记 FINDING、该拍名重入豁免册待复裁、当批起滚动删除挂起；
- **墓碑写失败**：删除批次整批 abort（§3.4 (iii)），禁止「先删后补碑」；
- **豁免册不可读**：fail-closed 全停（§2.4）；
- **双通道持续不可达**：沿 R2B-03a 限窗降级阶梯（RATELIMIT-GOVERNANCE-20261026-01 §6）挂起删除，不降级为单通道放行。

**4.3 回滚（被删拍恢复）。** 回滚路径依 mapping 去向双轨：(i) 对象库轨——`git cat-file -p <历史blob>` 复原（对象库为唯一承重墙，J-ADJ3 案一在案）；(ii) 归档轨——自 aggregate 摘要/ledger 行按偏移键提取并以 sha256 对拍验收。回滚事件（拍名/路径/依据/时刻/执行席）入 FSL 并在墓碑 `mapping` 旁补一行「已回滚」注记（注记为追加，不改原碑）。

**4.4 回滚演练义务。** 机制部署验证期（条款六 P-1）内必须完成 ≥1 次真实回滚演练（任选一已删拍走全程），未演练不满足生效前置。

## 条款五 · 与振荡列举面（A3 定谳，引用链更新至 R2B 案 A——C-10 落实）的相容性论证

**5.1 前提更新（C-10 落实）。** A2 之「稳态恒 3999 名序截断」表述已经 **J-R2 案 A 终裁**降级（`board/ADJUD-R2B-20261026-01.md` 案 A：WQ2-1 焦点裁②限定注记**转正为裁决条文**、A2「恒 3999」表述降级登记在案）：readdir 实为**缓存调制的名序前缀振荡列举**——实测可见域 3999–4438、下底约 3999、分钟级振荡，且观察者自身 stat/ls 加热缓存改变被测量（单 stat 使可见数 3999→4188 实测，A3 件）。「截断风险已消除」类表述**禁用**（WQ2-6 裁决）——REDUCE 消除的只是截断的**可见性触发面**，不是 portal 列举行为本身。

**5.2 相容性逐点论证。**
- (i) **删除面不依赖 readdir**：条款三 §3.2 枚举唯一钉 `git ls-files`（读 index/HEAD，不经 portal 工作树列举层），振荡列举对删除集生成**零影响**——相容；
- (ii) **sha256 实测依赖 by-name stat/读**：A3 证 by-name 访问可暂态 ENOENT（OBS-α 翻转、复验回返在案）；故 §3.3 之 sha256 实测失败**不得**直接判异常删除——沿三次复核闸（间隔 ≥5min、全部失败方成立，W2-P0-03），暂态失败只登记观望态重试；复核后仍失败则整批 abort（§3.3 C-5 落实文字）——相容（已内建）；
- (iii) **观察者效应隔离**：墓碑生成批次的校验读（sha256/stat）本身加热缓存，可能把名序线后件「挤回可见」——但本机制一切计数与枚举不以 readdir 为真值源，挤回不产生误判通道；监视侧之三遍采样取极差纪律（A3 建议 1）与本机制并行不悖——相容；
- (iv) **传感器空缺**：REDUCE 生效后 weave/pulse 恒 <4000，全仓无目录触振荡下底，3999 行为监视面归零（WQ2-6 成立在案）——本机制**不自含**该替代，条款六将「canary 恒压目录上线」列为生效前置（W2-P1-10 裁决：untracked 区恒压 4100 件占位、每批三遍计数），以条款间衔接消解该不相容点；
- (v) **墓碑目录自身**：`pulse-archive-index/` 为低频小目录（量级 = 删除拍数/周期），恒远离振荡下底，且其完整性经 git 对象层核验不依赖 readdir——相容。

**5.3 结论。** 在「枚举唯一 git ls-files + sha256 三次复核闸 + canary 前置」三条件下，墓碑映射机制与 A3 定谳（经 R2B 案 A 终裁层确认）之振荡列举模型无冲突；任一条件撤除则本相容性论证失效，须复裁。

**验收判据：**
- E1：三条件在草案条文（§3.2/§3.3/条款六）逐字可指；
- E2：部署验证期内对 weave/pulse 执行三遍 readdir 计数取极差留痕一次（沿用 A3 纪律），证明验证环境对振荡行为有基线读数；
- E3：草案全文无「截断风险已消除」及同义表述（grep 机检）。
