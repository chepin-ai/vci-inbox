## 三、异见收割与逐条评估

### 3.1 案 (a)

**D-a1（可信度异见）：降级是否削弱框架对外可信度？**
评估：不推翻。反向成立——维持「无证据之断言」才是可信度风险源：一旦外部按 lean-lang.org / MIP*=RE 审计段同款口径点破「kernel 通过 ≠ 陈述忠实」，损害大于主动降级；主动降级且附带审计义务本身为诚实信号。但异见揭示真实削弱点：降级行文若措辞不当，可能被误读为「本包定理未证」的暗示。→ 转定向补强（BC-A1），不推翻初裁。

**D-a2（执行钩异见）：降级后审计义务的执行钩在哪？**
评估：不推翻但实质削弱。呈批仅言「列入旗舰示范案例轨任务单、以 W-NS-03 重铸终稿 diff 为首件实做（G0-5）」，未钉归属线、未钉钩件载体、未钉截止/复查窗；无钩义务等同空义务，历史上「列入任务单」无下落即挂账再生。→ 转定向补强（BC-A2），初裁方向维持、义务配置须修正。

**D-a3（过渡期外溢异见）：帧 v1.2 在位期间 §4.3 原文断言仍是对外可引形态，降级裁后至新修订版落地前的窗口内是否存在断言外溢？**
评估：不推翻但成立。v1.2 变更日志仅载「呈批指针」，未载裁决结果；窗口内单独引用 §4.3 原文者无法从帧面直接读出降级状态。→ 转定向补强（BC-A1 第 3 款过渡期引用闸），不推翻初裁。

### 3.2 案 (b)

**D-b1（悬空钉异见）：12-hex 非永久形式在外部引用中是否会产生悬空钉？**
评估：不推翻但成立。草案 §一已声明对外发布须同时给出 https 形态或 40-hex 全钉，§四4(b) 已要求随载 40-hex 解析凭据；但「仓历史增长致歧义化」的风险不以外部/内部为界——仓内引用同样可能在历史增长后失配，且 yaml sources 类文件一旦外溢拷贝即实质外部化。草案对「失配后的存量引用处置」仅有 fail-closed 拒绝 + 换钉重锚，未设存量普查钩。→ 转定向补强（BC-B1 使用限制 + BC-B3 升格与普查），不推翻初裁。

**D-b2（fail-closed 历史兼容异见）：fail-closed 对历史文献中未注册 authority 的兼容性？**
评估：不推翻。事实面：截至 2026-10-23，qf-os URI 在册实例仅 formalization.yaml L25 一例，authority=`vci-inbox` 即在册；检索式③ 0 命中证无外部使用，历史兼容面为空集。原则面仍须防「未来发现历史件含未注册 authority」场景：fail-closed 拒绝**解析**不得演变为否定历史件**存在性**或诱发追溯改写。→ 转定向补强（BC-B2 登记事件 + 禁追溯改写法），初裁维持。

**D-b3（scheme 名冲突异见）：qf-os 仅内部登记、无外部协议登记权威，未来与外部 scheme 撞名时内部语义是否受污染？**
评估：不推翻。内部 scheme 与外部命名空间本就分离；草案 §一「对外发布场景须同时给出 https 可公开获取形态或 40-hex 全钉」已切断裸 qf-os URI 外流主通道。残余风险仅在外溢拷贝场景，已由 D-b1 之补强覆盖。→ 维持初裁，引用 BC-B1 第 2 款作防御性确认，不另立条款。

## 四、定向补强条款

**BC-A1（降级措辞钉——降级成文时必须逐字携带的三段式）**：框架线落帧新修订版时，§4.3 该条改写文本必须同时具备以下三要素，缺一不开版本程序：
1. 待审假设式表述：「**自评未见对齐缝，三层审计待排期**」（逐字，语义等价改写须呈判定席复核）；
2. 边界声明：明示 kernel 层验证在位（零 sorry、公理仅 `[propext, Classical.choice, Quot.sound]`）仅证类型层通过，**不证**「定理陈述忠实于自然语言原意」，后者属独立审计事项——使降级不被误读为对已证内容的否定（对应 D-a1）；
3. 过渡期引用闸：自本裁决日起至新修订版落仓，任何对外引用 §4.3 该行者必须同引 v1.2 变更日志纪律注记与本裁决（ADJUD-20261023-02），不得单独引原文断言式表述（对应 D-a3）。

**BC-A2（审计义务执行钩）**：审计义务配置为——归属线：框架线（旗舰示范案例轨）会同忠诚审计规程线（L34 规程线）；载体钩：G0-5 任务单成文落仓（W-NS-03 重铸终稿 diff 为首件实做对象）；复查窗：自首件实做落仓起，每批续扫监视件附带「U-23 审计进度」一行直至三层审计落地；落地前断言式表述禁令持续有效（对应 D-a2）。

**BC-B1（12-hex 使用限制条款）**：
1. 12-hex 短钉**仅限仓内机读场景**使用（yaml sources、帧证据锚、裁决格登记之内部引用）；凡对外发布件、对外可访问镜像、跨仓引用，一律使用 40-hex 全钉或 https 形态，12-hex 形态在外发件中视为格式错误（对应 D-b1/D-b3）；
2. 12-hex 引用随载 40-hex 解析凭据为**强制项**（草案 §四4(b) 由「登记」升格为「缺一不成立」：无随载全形凭据之 12-hex 引用不予解析登记）；
3. 仓历史重写事件（rebase/force-push/链嫁接）发生后首批续扫，监视件必含「在册 12-hex 引用可达性普查」一项（事件驱动，W30 合规），失配即按草案 §四4(c) fail-closed 登记并呈裁，禁静默重锚。

**BC-B2（fail-closed 历史兼容条款）**：解析器对未知 authority 拒绝解析时必登记事件（authority 字面值 + 出处件 + 时点），不得静默丢弃；若登记事件揭示历史件含未注册 authority，处置路径为「先入映射表、再解析」，**禁止追溯改写历史件内 URI 原文**（append-only 纪律延伸，对应 D-b2）。

**BC-B3（锚例升格与 U-04 销账出路择定）**：两可出路中本席**择定「内部登记解析规则」为主出路**，同时课升格义务——formalization.yaml v0.5 落版时 sources[0] 之 qf-os URI 由 12-hex 升格为 40-hex 全钉形态（58dfb9a94311 之全形以解析凭据留痕为准），短钉形态仅作历史留痕；升格完成且本规则经 vci-ledger 线登记在册后，U-04 转销账流程。
