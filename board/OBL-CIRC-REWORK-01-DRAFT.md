## 1. 问题重述：结构性不可验证的双根因

CERT-CIRC-LEAN-01 证书族（主件 + family×5，扩批后口径 10/10 inside=True）在 drift 修复后
阐释层全绿（ELAB_OK），但 **native_decide 恒 false**。FINDING-04 实锤两根因：

- **根因一 · `Expr.log` 缺位**：leancert 的 `ADSupported`/`checkADSupported` 自功能引入提交
  `4bf84ea91` 起即不含 `Expr.log`；而 circSystem 全部方程（11/11、19/19）均含
  `Expr.log (Expr.const 6)` 及 `log Σ exp(·)` 项 → 检查器按设计拒证。
  证据锚：探针实测 `checkADSupported` 11/11=false（`centerInside=true`，即唯有 log 一环卡死）。
- **根因二 · `Matrix.det` 不可计算**：leancert 非奇异前置检查所用 `Matrix.det` 为 Leibniz 定义，
  n=11/19 组合爆炸不可机算；leancert 自测仅覆盖 Fin 2。
  证据锚：FINDING-04「`Matrix.det` 为 Leibniz 定义」节。

结论口径（沿用 FINDING-04）：该族在其自身钉定的 leancert v4.34.1（`7f91b6eb35`）下
**从未 Lean 编译验证通过**；认证实际承载层 = Python 区间算术（Krawczyk 内包判据，
EXT-WAVE-03 既成 + EXT-WAVE-05 复验批 10/10 inside=True、负控全拒证，
`artifacts/CERT-CIRC-LEAN-01/family/EXT05-BATCH-01-RESULTS.md`）。
现 Lean 件性质 = 「形式化陈述稿」而非「机器验证证书」。

## 3. 技术路线候选

### 路线 A · log 消除（方程层改写）
将 `fᵢ + log 6 + log Σⱼ exp(gⱼ − C[i][j]) = 0` 指数化为等价无 log 形式
`6·Σⱼ exp(fᵢ + gⱼ − C[i][j]) − 1 = 0`（log 单射 + 指数和恒正 ⇒ 根集等价，盒上严格成立）。
改写后系统仅含 exp/add/neg/const，落入 ADSupported 现有支持域。
- 可行性：**高**。等价性为一行级数学事实，Lean 侧可作引理陈述；Python 层可先全量预检改写后
  系统的 Krawczyk 内包（Jacobian 改变，须重算预条件子与 K 宽）。
- 工作量：**小-中**。10 例方程机械改写 + Python 重验（脚本可 1:1 复用 EXT05-BATCH-01_verify.py
  骨架）+ Lean 件重生成。
- Python 层复用度：**高**（判据、有理中心、盒半径、负控向量全部沿用）。
- 致命短板：**只封根因一，不触根因二**（`Matrix.det` 仍不可算）。单独采用不足以达成目标。

### 路线 B · 见证证书化（预计算见证 + 可计算核验）
Python 区间层产出显式数值见证：区间端点（有理，limit_denominator 精度登记在案）、
有理预条件子 C、Krawczyk 像盒各端点、以及 Jacobian 非奇异的**可计算证据**；
Lean 侧只做可计算的证书核验——绕开 Leibniz `Matrix.det`，改用：
  (i) 预计算行列式值 + 恒等式核验（如 det·adjugate = det·I 逐元有理等式 by decide），或
  (ii) 可计算行列式实现（**有理 Bareiss 无分式消元**，n=11/19 精确整数运算，
      复杂度 O(n³) 大整数，native_decide 可及），
      辅以「可计算 det = Matrix.det」一次性桥接引理（Leibniz 层证明一次，全族复用）。
- 可行性：**高**。信任基清晰：Python 仅为见证生成器，Lean 核验不信赖 Python 正确性
  （见证无效则核验 fail，fail-closed）。
- 工作量：**中**。需新设见证证书 schema（可参照 EXT05-BATCH-01-results.json 既有字段扩展，
  schema 版本化纪律见 §9）、Bareiss/恒等式核验器（可复用 CERT-LATTICE-LEAN-01 /
  CERT-K4-LEAN-01 的 by decide 族经验，二者公理审计双干净 @3a5edd44）、桥接引理一件。
- Python 层复用度：**高**（区间端点、有理中心、预条件子均已产出并登记，扩批四例有理中心
  已在 RESULTS.md 备 Lean 移植段列出）。
- 优势：**同时封两根因**（log 由见证核验的区间界覆盖，或叠加路线 A 彻底消除；
  det 由可计算实现替代）。通用性强，可沉淀为联邦「区间见证→Lean 核验」模板。

### 路线 C · leancert 上游扩展探针（ADSupported 加 `Expr.log`）——含探针权限边界条款

- 工作量：本联邦侧小（patch 起草），但关键路径外置。
- Python 层复用度：高（与重做正交）。

### 路线 D · 判定核分治（per-instance 小核 + 全族元定理）

## 4. 验收判据（谓词化/布尔化 · 可脚本判定 · EXT09-R1 重写）
每条判据给出**布尔谓词 + 判定脚本接口 + 正证据要求**；判定程序输出逐条 true/false 及证据指针，任一 false 即整体不通过（合取，无析取豁免；默认拒绝律：证据缺失视同 false）。

- **AC1（核验通过）**：`∀ i ∈ 10例: verify(i) = true`，其中 verify(i) =（钉定 leancert 下 `native_decide`=true）∨（显式 checker 返回 true ∧ `verify_proof` 留痕文件存在 ∧ 复跑脚本 `replay(i)` 逐字节一致）。正证据 = 每例 {instance_id, verify_output_sha256, replay_run_id} 三元组落板。
- **AC2（支持域覆盖，路线 A 叠加时适用）**：`∀ i: checkADSupported(system'(i)) = (11/11 ∧ 19/19) = true`。脚本直读检查器输出，布尔向量逐项登记；不适用路线 A 时本条标记 `not_applicable=true` 并附路线登记指针（`not_applicable` 亦须显式登记，禁止静默跳过）。
- **AC3（公理审计干净）**：`∀ i: print_axioms(i) ⊆ {propext, Classical.choice, Quot.sound} ∧ sorryAx ∉ print_axioms(i) ∧ |print_axioms(i) \ baseline| = 0`（baseline = CERT-LATTICE-LEAN-01/CERT-K4-LEAN-01 标准公理集）。正证据 = 全族公理集清单哈希。
- **AC4（双层一致 + 失败路径可复现）**：`∀ i: lean_verdict(i) = true ⟺ python_inside(i) = true`（10/10 逐项对齐）**且** 负控可复现：`∀ 负控向量 g' = g+1e-6: lean_verify(g') = false ∧ python_inside(g') = false`（fail-closed 双向实证；负控脚本与正例脚本同源、同环境指纹，复跑结果逐字节一致）。**失败路径不可复现（负控复跑结果漂移）即 AC4=false**。
- **AC5（pin 完整 + 时序单调）**：`artifact_pin.oid = build_env.leancert_oid`（全 sha 比对，禁 tag）∧ tag 漂移监控条目 ts ≥ 本波次开工 ts；**时序单调**：每例证据链 `ts(witness_gen) < ts(lean_verify) ≤ ts(落板)`，事件序号单调（同 cache-anchor 案 §2.5 日志纪律）；时序倒挂或序号断裂即 AC5=false 并触发证据链审计。

## 9. 证书 schema 版本化与向后兼容策略（EXT09-R1 新增）
- **版本字段**：见证证书与一切批处理结果文件（EXT05-BATCH-01-results.json 及其后继）首字段必须为 `schema_version: "<major.minor>"`；缺版本字段的文件，判定程序拒绝受理（默认拒绝律延伸至格式层）。
- **兼容策略**：major 变更（字段删除/语义变更）不允许向后兼容豁免——旧版本证书须**一次性迁移脚本**升级并保留原件哈希与迁移映射表；minor 变更（纯增字段）向后兼容，旧件免迁移但须在读取时以缺省值显式补全并登记。
- **核验器-版本绑定**：核验核按 schema major 版本分派；核验器遇到高于自身支持的 major 版本 → fail-closed 拒验并登记 `unsupported_schema`，禁止静默降级解析。
- **旧证可解析义务**：本 OBL 存续期间签发的一切证书，其 schema 版本对应的解析器/核验器版本指针随证书一并落板，保证任意历史证书在冻结期后可被原样复验。

## 10. 证书签名闭环条款：外部签名或独立核验面（EXT09-R1 新增）
- **问题**：路线 B/D 下见证由联邦 Python 层生成、Lean 层核验、结论由联邦自证——全链内生构成自签闭环风险，「联邦证明自己正确」不构成独立可信。
- **条款（二选一，择一路线 M3 前由判定席裁定）**：
  1. **外部签名**：重发证书须获联邦外独立主体签名（候选：Axle 云端验证通道的独立 request 链 + 上游/第三方核验服务；签名覆盖 artifact_sha256 + schema_version + env_fp），签名记录与证书配对落板，缺签名证书不得宣称「机器验证证书」全级口径；
  2. **独立核验面**：复用 A1 堆叠案 L2（Lean4Lean 外检层）或同等级第二独立实现对重发证书做独立核验，双独立实现结论一致方可升级口径；分歧即 DISPUTED，按 A1 案 §4a 停层处置。
- **底线**：两条均不可行时，证书口径降级登记为「内生核验证书（fail-closed 见证核验）」，禁止升格「机器验证证书」，并如实载入对外文稿口径。
- 与 AC1 的关系：AC1 谓词不变（内生核验通过仍为先决）；本条是 AC1 之上的**口径升级门**，二者不可互替。
