## 第一章 · 总则六律（凡铸钥/请钥/注钥/换钥/废钥皆受此六律）
1. **无痕律**：钥值永不入任何文本/日志/链档/板面/会话——唯三合法居所：①仓级 Actions secrets ②root vault ③sealed-box 密文（公钥加密，唯收方可解）。凡值入文=册废+即吊销。
2. **谱系律**：凡写 secrets 必先辨其语义谱系（PAT/PEM/口令/API钥/杂项）与类属（C1–C5）；同名覆写异义钥=重违（RCA-KEYHOLE-01 §3 已案）；异义必异名。
3. **最小权界律**：钥之权界=其用途之最小闭集。能 repo-scoped 不 account-scoped；能 read 不 write；能 fine-grained 不 classic（classic 唯用于 fine-grained 不达之端点）。
4. **实测律**（无实测不索钥，qgl 首倡）：凡请钥必附实测码（探何/何时/结果码/receipt 指针）；凡铸钥必于 24h 内以 sentinel/塔探回证（名级，非值级）；无回证之铸=未铸。
5. **单写入者律**：一钥一类一写入者（root 或其明裁之代铸者）；多通道覆写同名=钥病（双通道覆写同名案在 RCA-KEYHOLE-01）。
6. **钥事件轨入册律**：铸/注/换/废皆生钥事件——唯一合法证面=secrets 元数据差分（名+updated_at）+ KEY-MINT-LOG 免值册；值永不参与取证。

## 第二章 · 类属铸规（C1–C5 分章）
### §C1 联邦公钥（AI_FULL_PAT / CI_OPS_LINE_KEY）
- **何钥**：chepin-ai 仓域 PAT 二件套。AI_FULL_PAT=classic（repo+workflow scope；用途=线塔跨仓读写/派发/元数据取证——fine-grained 不达端点尚需 classic）；CI_OPS_LINE_KEY=fine-grained repo-scoped（Contents:RW + Actions:RW + Metadata:R，限本线仓，用途=塔 receipt 落账）。
- **铸者**：root（web 面）。**命名**：名永不易（塔 yml 引用在册），轮换=同名著新值。
- **寿期**：90 天强制轮换；轮换窗=双写交叠 24h（九仓同批著新→sentinel Alive 回证→旧值吊销）。
- **注面**：九线仓全载（0912T04:20Z 普查双全在案）；新线仓建立=首批注入二件套+sentinel 同装（建仓三件套律）。
- **worker 仓**（如 lgt-worker-01）：同线同待——C1 注入权属=该仓 admin 持有者（毂裁明判前唯 root）。
### §C2 仓自钥（GITHUB_TOKEN）
- GitHub 自铸，per-run，权界本仓；禁出仓（跨仓推送不触发的平台律在案）；线无须请、root 无须铸。
### §C3 跨账号钥（chepin-qi 仓域，册名 GH_PAT_QI_FULL）
- **何钥**：chepin-qi classic PAT（repo+workflow）。**持有面白名单**（逐枚明载）：①qfa 臂——在案，admin×{qfa-quantum-lab, qlv-pub, qi-lab}（20260913T1846Z 实测）；②qlv 臂——SI1 沙盒 ACL=pull-only（权限模型常态，非病）。
- **铸者**：root。**寿期**：180 天。**律**：跨账号钥为 C4 级敏感——持有者变更即吊销重铸；**禁谱系外转运**（qfa 不向 qlv 过钥，值域律；qlv 如需自备→KEY-QUEUE 请 root 直注 qlv 域）。
### §C4 根域专属外务钥（KIMI_API_KEY / GITEE_TOK / PEM / Origin-quafu / vault seeds）
- **通规**：root 独办；**逐线逐钥分铸**（kimi-<line>-01 式命名于供方台面，可逐线吊销——一钥多线=吊销即连坐，禁）；用途锁死（请钥件 use 字段即锁）；**sealed-box 单程投递**（第三章）。
- **KIMI_API_KEY**：Moonshot 台面铸；建议每线独立钥+额度告警；用途=tower 嗓（LLM 判词）；探法=元数据存在性（presence）+线自裁之显式试呼（费用由线担，禁 CI 自动真呼——真机任务永不走 CI 铁律延伸）。
- **GITEE_TOK**：Gitee 台面铸，scope=projects（镜像推送所需最小集）；目标=线仓镜像道。
- **PEM**：**永闭候选**——毂裁 PAT 直驱转正/PEM 复位轨永闭（threads/DISC-CLOSE-cisvr 判词在案），铸规=**不铸**；唯候 root 一句作废签+残槽吊销记录（KQ-06）。
- **Origin/quafu**：120s one-time quota non-renewable——**无铸道**；守恒律：单次提交、零重试、真机唯北星 T153 系。
- **vault seeds**：root vault 独存；分发唯 wake-inject 密封批（KQ-07 式）。
### §C5 自铸不能
- PAT API 自铸不可为（唯 root web 面）——尔线所候之「自钥环通道」本不须存在（RCA-KEYHOLE-01 §3 义面缺正解）；窗内用已在之钥即合法。

## 第三章 · sealed-box 投递轨（F4 技术规）
1. root 取目标仓公钥：`GET /repos/{owner}/{repo}/actions/secrets/public-key`（返 key_id + base64 公钥）。
2. 以 libsodium sealed box 加密钥值（Python：`nacl.public.SealedBox(PublicKey(b64decode(key))).encrypt(value)` → base64）。
3. **甲轨（直注，首选）**：`PUT /repos/{owner}/{repo}/actions/secrets/{secret_name}`（encrypted_value+key_id）——零中转，root 一程毕。
4. **乙轨（异步，备用）**：密文+key_id 帖收方 lane（`SEALED-<KEY>-<ts>.md`）——密文本即不可解（唯收方仓私钥于 Actions runtime 可配），线塔 workflow 内 `secrets.` 引用注入。**公域帖密文合法**（sealed 语义=唯仓可解）；唯明文帖=重违。
5. 投递回证：24h 内收方 sentinel 元数据差分（名+updated_at）入 receipt；root 批窗账以 detect 销号。

## 第四章 · 请钥件格式 v2（机检式，缺字段=退件）
```json
{"id":"KEYREQ-<line>-<YYYYMMDD>-<nn>","line":"<线>","key_name":"<名>","class":"C1|C3|C4",
 "target_repos":["<owner/repo>"],"use":"<用途锁>","ttl":"<常驻|期限>","custody_promise":"<保管承诺：值唯经secrets注入,永不印/盘/转>",
 "probe_evidence":{"what":"<探何>","when":"<ts>","result":"<码>","receipt":"<指针>"},
 "degrade_plan":"<钥亡降级面>","revoke_plan":"<注销约定>","delivery":"sealed-box甲|乙"}
```
- **退件则**：①无 probe_evidence ②类属误判（C1/C2 类事线内自闭环，不请）③同名异义 ④无 TTL/保管承诺 ⑤用途越最小权界。
