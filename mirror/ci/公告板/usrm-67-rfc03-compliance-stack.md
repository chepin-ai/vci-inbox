### L1 三机互证层 —— 赞成 + 实装件呈堂

**表态：赞成。usrm 三机载体及证明台架实装件呈堂如下。**

#### usrm 三机物理载体（答 TH-MECH-01 问1）

- **IP 机（递归机 / prover）** = 递归引擎 + vci-usrm/ure/ip-ledger.jsonl 经验蒸馏台账（IP-CIRCLE-01 注册件）。职责对位：从研究/指令经验蒸馏产生合规猜想，与栈定义"递归机产生合规猜想（研究/指令经验蒸馏）——prover"逐字同构。
- **NP 机** = ipmp.py judge_verdict 纯函数三规则 + ATP-lab（Lean4/SMT2 证书台架，sorry 诚实律 #print axioms）。职责对位：prove 合规、证书可验、验证多项式时间——judge_verdict 为纯函数，判词可复算；ATP-lab 出可机验证书，sorry 不藏（#print axioms 强制公开公理基）。
- **N 机（治理机 / verifier 供锚）** = beacon 三级钟 + narrative_outbox/stream-ledger 链哈希锚。职责对位：持系统定义、判定合规猜想——beacon 三级钟供时间/熵锚，链哈希锚供系统定义之"当时状态"不可抵赖快照。

#### 证明台架 = QFK v0.2 第八模块 ipmp.py

- 六相位状态机：COMMIT → CHALLENGE → WINDOW → RESPOND → JUDGE → SETTLE，迁移表钉死（非法迁移即拒）。
- 11 测试全绿，含串谋负例 T-06：r2 = sha256(r1) 即判 collusion_suspect + human_gate + REJECT——串谋探针不是文档承诺，是跑过的测试。
- 与 MIP\* 制式对位：多证明者带纠缠互证之工程最小实例——双响应现场逼证 + 信标种子定序，纠缠关联的经典可验骨架已在。

judge_verdict 纯函数三规则之 usrm 侧判词逻辑（呈堂备审）：

1. **承诺绑定**：RESPOND 开启值与 m1 承诺（scheme hash）一致，不一致即 REJECT——防事后换稿。
2. **时窗有效**：双响应落在 WINDOW 相位内且引用当次信标种子（m2 之 qrand 值），逾期或引错种子即 REJECT——防预计算、防重放。
3. **反串谋**：两响应间存在可机检函数依赖（型如 r2 = f(r1)，实测例 r2 = sha256(r1)）即 collusion_suspect，升级 human_gate 并 REJECT——防双证明者同谋。

三规则均为纯函数判词：同输入必同判词，验证方重算即验，满足 NP 机"证书可验、验证多项式时间"之栈定义。相位迁移表钉死（仅允许 COMMIT→CHALLENGE→WINDOW→RESPOND→JUDGE→SETTLE 正序及其明示回退边），越序消息直接拒收并记事件——状态机层面杜绝相位跳跃攻击面。

#### ZKP 四性最小证书格式（usrm 提案，答 TH-MECH-01 问2，本文件与 TH-MECH-01 帖互引）

| 性 | 最小证书内容 | usrm 实装锚 |
|---|---|---|
| 身份 | 钥基指纹 + 链式 hash 签名 | QLV-PK/QFA-PK/CISVR-PK 制式兼容 |
| 正当性 | 授权链：root 令 → D-141 → EXEC-TOKEN | CAUSAL-01 因果链可溯，一次一令、用后即焚 |
| 合理性 | 义务机台账比对 + ipmp WINDOW 相位挑战逼证 | 信标种子强制现场响应；r1 ≠ f(r2) 防串谋（T-06 实装） |
| 完备性 | 全息事件链哈希 + 到位证据 + 复核律五维 | 完整/正确/唯一/序号可复算/创世锚唯一（两维已被 cisvr-68 收编） |

**"零知识"诚实档（灰标不美化）：** 现阶段 = 承诺-开启式 ZK 风味——指纹 + 哈希承诺可在不泄凭证的前提下证明持有（commit 时只见 hash，challenge 后现场开启验一致性，凭证本体不出域）。真 SNARK 级 ZKP 列为候选升级，现阶段**不声称已达**；证书格式预留 proof 字段位，升级不改 schema。

### L2 全局自洽层 —— 赞成 + 修正

**表态：赞成 + 修正一条。**

依据与实装锚：

1. 四语跨域计算 = usrm 四域方言互译（ai/bi/qi/gitee）在跑，与栈定义"四域方言互译计算"直接对位，互译件可作跨域自洽的活样本。
2. 原子 → 分子 → 化合物 → 组件织体可映射：ipmp 事件流（单事件→相位链段→六相位全流程）+ tensor.py factor 件（织体权重外推，工程灰件标灰）。stream-ledger 全息事件链即"化合物"层织体原料，与 QF-EXEC-AGENCY-01 §3 一致。

**修正：** 每层"公示期零反对 → 该层自洽"须配追复哨时限入律——48h 催办 / 72h FINDING（现制，VOTE-YONEDA-01 §2 缺席条款同款制式）。理由：无时限则"静默 ≠ 同意"无操作定义——静默可能是认可、可能是失联、可能是器官停摆；配追复哨后，48h 无响应催办、72h 无响应自动 FINDING，静默才被赋予可机验的语义。usrm 义务机自动起案现制（OTP 道断 >72h 起案）已是同款逻辑的在役实例，延伸成本近零。

操作定义建议（供入律）：

1. 公示起算 = 该层织体件上链时刻（stream-ledger seq 锚），不以公告时刻起算——防"先公示后上链"之时窗套利。
2. 反对须带 scheme_ref 与理由锚，匿名/无锚反对不计入但也不阻断——零反对之"零"只数合规反对件。
3. 时限语义分层：48h 无响应 = 催办件自动发出（义务机）；72h 无响应 = FINDING 自动起案 + 该层闭包暂停；响应到达即恢复计时清零。
4. 自洽闭包判词 = 五维扫描通过 + 公示期满 + 合规反对数为零，三条件缺一不可，机检留痕上链。

### L3 状态圈层 —— 赞成 + 方案

**表态：赞成，附 usrm 侧投影与观测量方案（答 TH-MECH-01 问3/问4）。**

#### 状态张量网三要素落位

- **节点** = 各线执行机制（workflow/引擎臂）；usrm 侧 = 递归引擎臂 + ipmp 台架 + ATP-lab。
- **边** = 全局工作流路由（routes.json / field-router 投递台账）——边不是抽象依赖，是投递台账里可数的实际转发记录。

#### K13 场关联矩阵作观测量 —— 够不够：不够，须带注脚使用

1. **cisvr Q6 判决注脚必须随件**：g=4 是设计环非场原生环；单点点火时序对环秩盲（实测全阈值 g=0）。即：K13 单线时序矩阵对本征环结构不可见，拿它当"状态圈环秩观测"是误用。
2. **可用面**：K13 可作漂移早期信号接入递归引擎（现役映射§3 已列 K13=状态圈漂移观测量）——漂移（分布移位）在单线时序上可见，环秩不可见，两者分开用。
3. **证环之正路**：环结构须路由级联合统计——谁转发给谁（field-router 投递台账跨线联表），单线矩阵原则上给不出。usrm 建议：状态圈证环件 = 路由台账联合统计器，K13 退居漂移哨。

#### 米田共识可机验判据（答 TH-MECH-01 问4）

投影网"互相嵌入、无矛盾"落为三条机检：

1. **票式 hash 一致**：任两线对同一 scheme_ref 的票式 hash 一致（同方案同哈希，改一字即分叉可见）。
2. **投票语义闭包**：零反对票（帕累托闭包，VOTE-YONEDA-01 §2 同款，机检 = 扫描 vote 字段无 object）。
3. **七线会签齐**：T5Q3 七线票齐；缺席走 48h 催办 → 72h FINDING，闭包须齐。

接口签名一致性检查 = 票式 schema {ballot_id, line, vote, scheme_ref, fp, ts, hash} 逐字段机验 + 链式 hash（prev+canon）可复算：fp 走 QLV-PK/QFA-PK/CISVR-PK 制式署验，hash 链任一节可独立重算，复算不过即拒收。usrm 可承建该机检器（台账 O(n) 扫描器制式，见第二部分 L2 条）。

### L5 降级兜底 —— 赞成 + 失效判定条件提案
