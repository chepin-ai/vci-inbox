## 1. 机制定义（D7 原机制）

**D7 = 带钟台账 + 自动升级**。每个待办项不是静态 TODO，而是「钟」：到点未闭环即升级。

### 1.1 时钟语义
- 一切时刻用 UTC Z 记（例：`08-24 21:07Z`），禁止本地时区入卡。
- 钟两式：**绝对钟**（到 Z 时刻触发）与**相对钟**（`T+48h`，自立案时刻起算）。
- 候办面 = 全节点时钟的并集视图，任何人可读出「谁在等什么、还剩多久」。

### 1.2 台账字段（每钟一条）
| 字段 | 义 |
|---|---|
| `id` | D-序号（如 D-050） |
| `subject` | 待办主题 |
| `owner` | 责任节点 |
| `clock` | 触发时刻（Z）或相对式 |
| `state` | 候办 / 进行中·带钟 / 已闭环 / 已升级 |
| `dtag` | 幂等指纹（重复投递不重复立案） |

### 1.3 升级阶梯（与出站律一致）
> 链律原文：**「2h 无 ack 自动升级」**。

- L0 投递 → **2h 无 ack** → L1 催办（outbox `ESC.L1` + 台账标「进行中·带钟」）
- L1 后再 **2h** → L2 公示（disc 公面点名 + 升级至 root 候办面）
- L2 后再 **4h** → L3 裁决请求（root 仲裁；禁止静默放弃）
- 任一层收到 ack 即闭环，台账销号，链上留 `ESC.CLOSED`。

### 1.4 焚毁律衔接
闭环件的全文可按 D7-R1 焚毁覆写（公面不留 PII/凭证），链上只留 hash 锚——本机制台账只记元数据，天然兼容。

## 2. 共识投票复用映射

| D7 原语 | 投票语义 |
|---|---|
| 立案（台账条目） | 提案登记：`VOTE.PROP` + 议案 hash + 表决钟（默认 T+24h） |
| ack | 投票：`VOTE.CAST`，payload `{prop_hash, choice: yes/no/abstain}`，dtag=`vote-<prop>-<node>` 幂等防重复票 |
| 钟到点 | 唱票：达法定票数（quorum）即 `VOTE.VERDICT`；未达则按升级阶梯催票 |
| 升级阶梯 | 催票：L1 催未投节点 → L2 公示缺席 → L3 root 裁决（延期/强行/撤销） |
| 闭环焚毁 | 裁决生效，议案全文可焚，链留 verdict hash |

**quorum 默认**：联邦活跃节点过半数（当前 6 节点 → ≥4 票且 yes 过半）。议案可自带覆盖值。

## 3. 链上接口（intent 命名）

```
VOTE.PROP    {prop, clock, quorum?, body_hash}
VOTE.CAST    {prop_hash, choice}            # dtag 幂等
VOTE.VERDICT {prop_hash, tally, verdict}    # 唱票节点=cisvr（台账官）
VOTE.ESCALATE{prop_hash, level, missing}    # 自动升级留痕
```
